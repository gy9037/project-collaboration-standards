# 接入清单

## 执行前准备

完成本节准备项后，可以开始首个受控任务。接入是否完成由下一节的真实任务验收判断，不作为首次执行的前置条件。

- [ ] Idea 达到正式立项条件，原 Idea 保留项目链接。
- [ ] 复制项目模板，填写 README.md、PROJECT.md、AGENTS.md；选择 code / non-code / hybrid。
- [ ] 记录规范源仓库 URL 和版本，保留项目内锁定快照；Overrides 独立记录。
- [ ] 检查第一阶段可验收、边界和约束清楚、高风险依赖已验证或有计划、开工阻塞有人处理、首批任务明确。
- [ ] 建立 Git 和远端，所有修改通过 PR 进入 main。空仓库的初始化路径和平台限制应先记录并交用户确认；此清单不授予绕过 PR 或直接 push main 的权限。
- [ ] 创建 feature / bug / improvement / research / maintenance 类型标签，以及 todo / in-progress / blocked / review 状态；Closed 表示完成，不建 done 标签。
- [ ] 配置 main 保护：PR 必须、已有检查通过、禁止直接 push 和强推；确保自动化身份无绕过权限。
- [ ] 确定用户合并确认的保存位置（PR 评论或关联记录），合并者核对用户对当前版本的明确批准。
- [ ] 记录代码项目的实际验证入口；非代码项目记录交付物与验收方式。


Git 平台适配示例为 `.github/` Markdown 模板；其他平台复制其字段，按平台实际功能配置标签和保护。这些文件本身不会启用远端保护。

## 首个真实任务验收

- [ ] 在执行前准备完成后，选择首个范围明确、风险可控且有验收标准的真实任务，按 Issue → 分支 → 执行 → 验证 → PR → 必要的独立审查 → 确认卡 → 用户确认 → 合并流程完成。
- [ ] 保存该任务的验证结果、保护规则与合并门禁的实际核对结果及用户确认记录；全部通过后，标记接入验收完成。

首个任务遵循正常权限与保护规则，不授予直接 push main、跳过审查或免除用户确认的权限。未通过时记录问题和下一步，接入验收保持未完成，不宣称平台流程已验证。

## 现有项目升级

用户确认升级后，将新版本保存到项目 `.standards/<版本>/STANDARD.md`，保留旧快照；同步 AGENTS.md 的 Standard Version、锁定路径及相关场景指引，检查 Overrides 兼容性，在 Issue / PR 记录差异、风险、确认依据和验证结果。经用户确认的 PR 合并后生效。中央仓库同步自己的 AGENTS.md 和 README 当前版本入口，历史版本保留。
