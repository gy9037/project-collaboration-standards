# 项目接入边界与接手事实源

状态：待合并规则提案。来源：2026-10-23 用户要求将工作台范围误判补入规范。此提案不覆盖 V1.0 正式版本，不自动升级旧项目。

## 问题

工具扫描到仓库、读取到会话或发现规则文件，并不能证明用户已经将该项目纳入当前协作范围。旧实现行为也不能反向定义用户的授权范围。接手遗漏事实源时，增加筛选器或要求用户重新选择不能替代核对已有记录。

## 接手规则

1. 先定位当前框架入口、显式项目索引和当前任务交接，核对各自版本与时间。目录中存在多套新旧工具时，确认哪套承担当前任务。
2. 按信息类别取事实源：规则看锁定版本；项目接入看登记和接入决定；任务进度看当前 Issue/PR；运行状态看本次执行证据。旧摘要、旧 README 和代码行为只作线索。
3. 用户已明确的范围作为核对约束。接手者先查已有证据，不把自己的漏读当成需要用户重新做决定。证据仍冲突时，只询问无法确定的具体取舍。

## 接入规则

必须分别记录：发现候选、显式登记、试点启用、正式迁移、业务验收。技术模式、文件存在、规则校验通过和历史运行成功都不能替代接入决定。

项目登记至少保存稳定标识、路径、负责人、共享声明。接入阶段另存状态、核对日期和证据；缺失为 unknown，不根据目录或模式猜测。已启用项目与 staging、暂停、未迁移、封存项目分开展示。总览和项目工作区共用同一接入集合；筛选与别名不改变接入身份。

发现候选不自动读取项目正文、关联任务或启动会话。跨项目读取遵守共享声明；写入通过目标项目的任务流程。任务必须显式关联稳定项目标识，不按名称相似度推断。

## 变更与封存

接入、暂停、迁移、封存保留依据、负责人、时间、原状态和恢复入口。用户要求重建工具时，保存源码版本、未提交修改和必要配置，校验备份可恢复后标记冻结；冻结不等于验收通过或合并。新版是否继承旧需求，按用户当前决定记录。

运行中的工作先到安全检查点；不可将“封存界面”扩大为删除业务资料、停止无关服务或改变其他项目的权限。

## 验收样例

| 输入 | 应有结果 |
| --- | --- |
| 扫描发现多个仓库，明确试点只有一个 | 当前工作区只有该试点；其余仅为候选 |
| 项目技术模式已迁移，接入记录仍为 staging | 显示准备阶段，不当作已启用 |
| 已启用项目缺少或损坏 lock | 保留接入身份，运行状态报错，受控写入拒绝 |
| 没有接入记录 | unknown，不猜测、不扩权 |
| 有历史成功 receipt，本次检查失败 | 显示本次失败，历史记录仅作审计 |
| 用户要求封存旧工具 | 有版本、备份、恢复说明；不写成已验收 |

## 生效与兼容

本提案经独立审查与用户确认合并后，作为后续正式版本编制依据。现有项目继续执行其锁定规范；需要升级时单独评估、审查与确认。框架工具可在本次用户授权的重建分支内先实现以上判定，但不得把分支实现宣称为已发布规范。
