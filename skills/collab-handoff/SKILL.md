# 任务交接与中断恢复

## 用途

落实规范第 8 条：进度不只留在本地和聊天里。离开的一方把状态写进当前 Issue，接手的一方按固定顺序恢复。

## 触发场景

交接（离开方）：

- 换执行者，或工作交给其他人员；
- 即将更换模型或 Agent；
- 暂停任务；
- 额度即将用完。

恢复（接手方）：

- 接手一个已有分支、PR 或交接评论的任务；
- 上一个执行者意外中断，没有留下交接。

不触发：

- 同一执行者在同一会话内连续工作；
- 任务已合并、Issue 已关闭（此时只需按 collab-merge 收尾）。

## 步骤

### A. 交接（离开方）

1. **保存进度到远端。** 已验证的阶段 commit；未验证的改动单独 commit，message 写明「未验证」。把任务分支 push 到远端。完成标准：`git status` 干净，`git rev-parse HEAD` 与远端任务分支一致。
   - 有改动不能提交（例如含凭据，见规范第 7 条）：不提交，在交接「风险」里写明它在哪台机器、哪个路径、为什么没提交。
2. **在当前 Issue 发交接评论**，标题「交接」，逐项填写：
   - 当前进度：处于哪一步，一句话；
   - 已完成：逐项列出，每项标注已验证 / 未验证；
   - 未完成：逐项列出；
   - 关键改动：改了哪些文件或交付物、为什么；
   - 风险：已知问题、未验证项、阻塞点、未提交内容；
   - 下一步：接手者第一件要做的事，具体到命令或文件；
   - 相关 commit / PR：分支名、最新 commit SHA、PR 链接（没有就写「无」）。
3. **决策点：是否需要独立交接文件。** 满足以下任一条才建，否则只写 Issue 评论：
   - 交接跨多个 Issue 或 PR；
   - 接手者需要的环境、背景说明超出一条评论能写清的长度；
   - 接手需要按顺序执行多步人工操作。

   需要时：按 `optional-templates/handoff.md` 新建 `docs/handoff/YYYY-MM-DD-<主题>.md`，随任务分支提交，并在 Issue 交接评论里链接该文件。
4. **核对。** 假设自己明天失忆，只读 Issue 评论和分支，能否知道下一步做什么。不能就补写。

### B. 恢复（接手方）

1. **按顺序读取**（规范第 8 条）：PROJECT.md → AGENTS.md → 当前 Issue（重点读最新一条交接评论）→ 当前 PR → 分支与 commit。不读旧聊天记录来补信息。
2. **核对分支实际状态。** 执行 `git fetch`、`git log origin/<分支> --oneline`、`git diff origin/main...origin/<分支> --stat`，与交接评论中的 commit SHA 和「已完成」对照。
3. **决策点：交接与实际不一致，或没有交接。**
   - 证据能确定的（例如交接写「未提交」但分支上已有对应 commit）：以证据为准，在 Issue 里写明修正。
   - 证据不能确定的：列出差异，交用户判断（规范第 1 条），等待期间只做不受该差异影响的部分。
   - 没有交接评论（意外中断）：根据 PR、commit、分支差异重建进度，在 Issue 发一条「中断恢复」评论，按 A.2 的字段写出重建结果，并单列「无法确认的部分」。
4. **在 Issue 发「已接手」评论：** 接手者、基于的 commit SHA、准备执行的下一步。然后开始工作。

## 示例

执行者 A 在做 Issue #42「导入页支持 CSV」，额度将尽。

1. A commit 已通过测试的解析器（`a1b2c3d`），把未跑测试的错误提示改动单独 commit 为「wip: 错误提示（未验证）」（`d4e5f6a`），push 到 `feat/42-csv-import`。
2. A 在 #42 评论：
   > 交接
   > 当前进度：解析完成，错误提示写了一半。
   > 已完成：CSV 解析（已验证，测试通过）；错误提示文案（未验证）。
   > 未完成：超大文件分批读取。
   > 关键改动：`src/import/csv.ts` 新增解析；`src/import/errors.ts` 新增提示。
   > 风险：错误提示未跑测试；样例文件 >10MB 时内存未测。
   > 下一步：运行 `npm test -- import`，修复 errors 相关失败。
   > 相关 commit / PR：`feat/42-csv-import`，最新 `d4e5f6a`，PR 未建。
3. 执行者 B 接手：读 PROJECT.md、AGENTS.md、#42、无 PR，`git log` 显示最新为 `d4e5f6a`，与交接一致。B 在 #42 评论「已接手，基于 d4e5f6a，先跑 import 测试」。

## 验收

交接：

- [ ] 任务分支已 push，本地与远端 HEAD 一致；未提交内容已在「风险」中说明
- [ ] 当前 Issue 有交接评论，7 个字段齐全，「已完成」逐项标注已验证 / 未验证
- [ ] 「下一步」具体到可直接执行的命令或文件
- [ ] 只有满足 A.3 条件时才建了 `docs/handoff/` 文件，且 Issue 中有链接

恢复：

- [ ] 按 PROJECT.md → AGENTS.md → Issue → PR → 分支的顺序读取，未依赖旧聊天
- [ ] 交接内容与分支实际状态已核对，差异已处理或交用户判断
- [ ] Issue 中有「已接手」或「中断恢复」评论，写明基于的 commit
