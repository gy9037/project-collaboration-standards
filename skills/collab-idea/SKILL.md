# 想法记录与立项判断

## 用途

想法先进 Idea Lab，不直接建项目。把想法从「一句话」推进到「能判断值不值得做」，Ready 后交给 collab-project-setup。

## 触发场景

- 用户说「我有个想法」「记一下」「这个值不值得做」。
- 用户要求评估、验证某个已记录的想法。
- 用户要把想法立项。

不触发：

- 已立项项目里的新需求 → collab-issue。
- 已有仓库要接入规范 → collab-project-setup。

## 步骤

1. **定位 Idea Lab。** 找到用户的 Idea Lab 仓库，先读它的 README.md 和 AGENTS.md。没有 Idea Lab 时，按规范仓库 `idea-lab/` 目录建立，位置问用户。
2. **捕获（Inbox）。** 复制 `templates/idea.md` 到 `ideas/inbox/<YYYY-MM-DD>-<短名>.md`，只填临时标题、原始想法（用用户原话）、记录日期。用户没要求分析时到此为止。
3. **探索（Exploring）。** `git mv` 到 `ideas/exploring/`。按模板补充：问题 / 对象 / 场景、预期价值、关键假设、已有证据。
   - 没有来源的判断一律标「假设 / 待验证」，不写成事实。
   - 证据写来源、日期、结论。
4. **验证（Validating）。** `git mv` 到 `ideas/validating/`。逐项写下面 8 项，不打分：
   价值、证据、可行性、成本（时间 / 资金 / 学习 / 维护）、风险、外部依赖、机会成本、最小验证方案。
   - 最小验证方案必须写成功标准和退出条件（达到什么就停、投入到多少就停）。
   - 能由 AI 自己完成的验证（查资料、跑原型、算成本）直接做，结果写回文件。
5. **决策点。** 对照立项条件逐条判断，写进「当前结论 / 下一步」：
   1. 问题基本明确
   2. 关键可行性已判断
   3. 关键假设已识别
   4. 综合价值、成本、风险后值得投入
   5. 第一阶段目标明确
   6. 当前范围和暂不做的内容明确
   7. 已知可执行的第一步

   | 判断 | 动作 |
   |---|---|
   | 7 条都满足 | 建议 Ready，附逐条依据，由用户决定 |
   | 可行但现在不做 | 建议 Parked，写原因和重新评估的触发条件 |
   | 触发退出条件或不值得做 | 建议 Dropped，写原因 |
   | 仍有缺口 | 留在当前状态，下一步写具体要验证什么 |

   投不投入是用户的取舍：AI 给建议和依据，用户拍板后才移动到 ready / parked / dropped。
6. **立项。** 用户确认 Ready 后：
   - `git mv` 到 `ideas/ready/`。
   - 转 collab-project-setup 建立正式项目。
   - 项目建好后回到 Idea 文件，填「正式项目链接 / 立项日期」。原 Idea 不删除。
7. **提交。** 按 Idea Lab 的 AGENTS.md 提交：任务分支 → PR → 按规范第 5 条判档合并（collab-merge）；提交前检查 diff 无凭据（规范第 7 条）。

规则：

- 一个想法只有一个文件，只在一个状态目录里；状态以所在目录为准，不在文件里另写状态。
- 状态目录首次使用时再建。
- 一次对话只推进到能推进的地方，未完成的写进「下一步」，下次从文件恢复。

## 示例

用户：「想做个自动整理家庭账单的小工具，记一下。」

1. 新建 `ideas/inbox/2026-11-25-账单整理.md`，填标题、原话、日期，回复「已记录」。
2. 一周后用户说「评估一下」。移到 exploring/，补问题（每月手工对账 2 小时）、对象（自己家）、假设「银行能导出 CSV（假设 / 待验证）」。
3. 移到 validating/，AI 下载两家银行的导出样例确认可行，写证据；成本约 3 个晚上；退出条件「2 个晚上解析不了两家格式就停」。
4. 7 条逐条有依据，建议 Ready。用户同意 → 移到 ready/ → collab-project-setup → 回填项目链接和日期。

## 验收

- [ ] Idea 文件存在且只在一个状态目录中。
- [ ] Inbox 阶段至少有标题、原始想法、日期。
- [ ] 未验证的内容都标了「假设 / 待验证」，证据有来源和日期。
- [ ] Validating 阶段 8 项都有内容，最小验证方案含成功标准和退出条件。
- [ ] Ready / Parked / Dropped 有用户决定记录和原因。
- [ ] 已立项的 Idea 保留在 ready/，填了正式项目链接和立项日期。
