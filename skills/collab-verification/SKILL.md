# 验收

## 用途

由执行者以外的验收者确认交付物满足 Issue 的每条验收标准，标出未验证内容，结果写回 Issue/PR，作为 collab-merge 判定档位的依据。

## 触发场景

- 执行者声明任务完成，Issue 打 `review` 或 PR 已开出。
- 验收退回后执行者提交了修复，需要复验。
- 用户要求对某个交付物做二次审查。

不触发：

- 免 Issue 的极小修改：执行者自查 diff 和验证入口即可，合并时没有独立验收者，按 collab-merge 走第二档。
- 执行中的阶段性自测，由执行者自己完成，不算验收。

## 步骤

1. **确认验收者**。验收者不得是该 Issue 的执行者（包括同一 Agent 的同一会话）。协调者自己执行的任务，交给另一个 Agent 或会话验收。找不到其他验收者时照常验收但标注「无独立验收者」，合并必须走第二档。
2. **收集材料**。读 Issue 的验收标准、PR 描述、`git fetch origin` 后的 `git diff origin/main...HEAD`、AGENTS.md 中的验证入口、PROJECT.md 的 Critical Areas。记录当前 commit。
3. **按项目类型验证**，自己重跑，不只看执行者贴的结果：
   - code：运行验证入口（测试、构建、静态检查）；对验收标准涉及的功能实际操作一次；能部署的环境按需做部署验证。
   - non-code：核对内容完整性、交付物与验收标准逐条对应、格式、数据和来源可查证、读者能照着操作。
   - hybrid：按交付物拆开，代码部分按 code，文档或内容部分按 non-code，分别记录。
4. **逐条对证据**。每条验收标准写一行：标准 → 方法 → 结果 → 证据（命令输出摘要、截图、链接、文件路径与行号）。没有证据的标准判为「未验证」，不得写「通过」。
5. **判断是否需要独立审查**。以下任一成立即需要，另找一个既非执行者也非验收者的审查者：
   - 修改核心功能、关键数据、基础架构、核心依赖或关键配置（包括 Critical Areas）；
   - 涉及账号、权限、密钥、安全、隐私、生产环境；
   - 涉及数据库结构或数据迁移；
   - 跨多个模块且回退成本高；
   - Issue 有较高复杂度或关键不确定性；
   - 存在无法充分验证的内容；
   - 用户要求。
   普通文档、样式调整、低风险小改动不需要。审查查五项：是否满足验收标准、有无副作用、验证是否充分、有无遗漏风险、有无未说明的范围变化。
6. **标注未验证项**。无法验证的内容逐项写出原因和建议验证方式。存在任何未验证项时结论只能是「部分验证」或「不通过」。
7. **写回结果**。在 PR 评论（无 PR 时写 Issue）按下方格式记录，字段与 optional-templates/verification.md 一致（含执行者、验收者）；同步更新 PR 描述的「验证方法与结果」和「独立审查」两节。
8. **按结论处理**（决策点）：
   - 通过：Issue 保持 `review` 待合并，转 collab-merge。
   - 部分验证：同样转 collab-merge，未验证项会使其进入第二档。
   - 不通过：退回原执行者。在 Issue 写明每个缺陷（现象、对应哪条标准、证据）和复验方式（复验时跑什么、看什么），Issue 改回 `in-progress`。修复后从第 2 步复验，只复验受影响的标准外加验证入口全量。

验收结果格式：

```
## 验收结果
验收者：<Agent/会话，或人员角色>（执行者：<…>）
commit：<sha>　环境与日期：<…>
| 验收标准 | 方法 | 结果 | 证据 |
|---|---|---|---|
未验证内容：<逐项及原因；无则写「无」>
独立审查：<需要/不需要及依据；审查者与结论>
结论：<通过 / 部分验证 / 不通过>
```

## 示例

PR #51 对应 Issue #42「导出报表增加日期筛选」，code 项目，执行者为代码执行 Agent，验收者为协调者。

- 运行 `npm test` 全部通过；本地启动后选择日期区间导出，行数与数据库查询一致；跨年区间无数据库可测。
- 不涉及 Critical Areas，未触发独立审查条件。

PR 评论：

```
## 验收结果
验收者：协调者（执行者：代码执行 Agent）
commit：a1b2c3d　环境与日期：本地 dev，2026-11-25
| 验收标准 | 方法 | 结果 | 证据 |
|---|---|---|---|
| 可按起止日期筛选 | 手动导出 11-01~11-10 | 通过 | 导出 37 行，与 SQL 计数一致 |
| 未选日期时导出全部 | 手动导出 | 通过 | 导出 512 行 |
| 有单元测试 | npm test | 通过 | 3 个新用例通过 |
未验证内容：跨年区间（测试库无跨年数据），建议补造数据后验证
独立审查：不需要，单模块低风险
结论：部分验证
```

## 验收

- [ ] 验收者与执行者不同，或已标注「无独立验收者」。
- [ ] 每条验收标准都有方法、结果和证据；无证据的标为未验证。
- [ ] 未验证内容已逐项列出，结论与之一致。
- [ ] 已判断独立审查是否需要，需要时有审查者和结论。
- [ ] 结果已写入 PR 或 Issue，记录了 commit。
- [ ] 不通过时缺陷和复验方式已写入 Issue，并退回原执行者。
